# 贾维斯只读能力与组织任务引擎实施记录

## 授权与验收边界（2026-11-16）

用户确认前期大脑只暴露 read 类型直接工具，保留任务查询与交办作为独立调度能力；每个组织应能管理实际生效的内部任务引擎。普通本地制作任务不以 GitHub 为前置条件。用户随后授权核对边界并实施。

- 大脑可读取已授权资料、查询真实运行信息、进行确定性计算；不能直接写文件、执行命令或通过其他工具绕过限制。Worker 权限独立。
- 工具目录保留已关闭且实际可用的只读工具；未接入能力不提供假开关。
- 任务引擎配置必须绑定当前组织、持久保存并由同一个真实执行链消费；不能把旧全局设置页嵌入后声称实现隔离。
- 新本地任务使用受管理的任务目录，后续要求继续同一任务，交付真实成果；GitHub 只在明确项目上下文下使用。
- 保留已有对话、任务归属、组织配置及显式 GitHub 工作流；不自动重放未知结果任务。

## 影响分析

当前日常对话通过旧单实例 Gateway/执行服务交办；组织设置管理的是独立业务进程。仅修改界面或提示词无法让组织 Worker 设置影响日常交办，也无法可靠约束大脑写操作。需在 Jarvis 适配层衔接组织执行链，并为独立进程补充实际消费的配置；优先复用现有 Core、Gateway、授权与持久状态，不进行无关领域重构。

只读策略同时作用于模型工具目录和调用守卫。任务交办属于显式例外，不能被泛化为文件或外部系统写权限。提示词不承担授权校验。新增配置只包含已实现的选择；现有来源能力不足时不展示可保存空壳。

### 完成后继续修改的领域影响

既有 Core 已有真实用户消息恢复已完成任务的机制，但 Gateway 的固定命令路径一律拒绝已结束目标。为了让本地成果后续修改继续原任务和目录，独立组织引擎会显式启用“人工追加到已完成且授权仍有效任务”能力；沿用原 attach/wake、授权复核及幂等收据。人工停止、撤销授权、机器追加和其他结束状态仍拒绝。旧执行服务不启用该能力，现有语义保持。该内部能力不是新增用户开关，验证覆盖原任务与目录保持、真实追加、重复请求及人工停止拒绝。

## 已实现行为与入口

- 组织内导航：组织信息、贾维斯、任务引擎、连接与资源、部署与运行。任务引擎包含任务来源、接单与路由、Worker、工作空间与交付、提示词；旧 router/worker 链接兼容。没有新增虚假的来源开关或 GitHub 必填字段。
- 当前日常贾维斯的直接工具限 read、read_image、glob、grep、current_time、calculate、web_search、web_fetch，网络项仅在真实提供时展示；独立列出任务查询/交办。写入、命令及未知工具同时受模型目录与执行守卫限制，旧保存值不扩大权限。时间读取真实时钟，计算器不执行代码。
- 每个组织独立保存 Router/Worker 的现有模型、工具、技能和并发配置；增加五段实际消费的执行提示词：接单与路由、Worker、沟通、任务范围、交付。默认资源在 `prompts/process-runtime/`，修改、草稿恢复默认、有效文本预览与版本冲突保护均接通。
- 日常新任务进入 root 的真实 ProcessRuntime/Gateway；旧任务仍归原执行服务。持久登记归属、未知结果不换引擎重发、反馈沿实际任务返回，旧通知清空/代次切换需原账本可用。
- 新本地任务按任务分配工作目录，已存在任务（包括已完成历史任务）保留原目录。只读相对路径优先任务文件，缺失时查找组织资料；文件写入仍限任务目录。工作目录约束不是操作系统沙箱。
- Worker 报告登记真实文件；程序生成打开/下载入口，主对话独立展示，不依赖模型抄写链接。下级成果使用固定父子任务绑定验证的结构化数据回传，不把摘要文字当作文件访问授权。
- 本地已完成任务可在原授权有效且用户明确选择后续改；**已完成的下级委派暂不支持原任务续改**，明确拒绝，不能静默另建子任务。运行中的下级追加/回答/停止保持原机制。
