## 行为与配置

- 实例编辑改为“组织与大脑 / Worker 设置 / 下级委派 / 部署与运行”。组织职责和能力标签用于上级 Router 的实例目录；不会安装技能或授予工具。
- Worker 设置集中普通 Worker 的模型、工具、技能、并发。实际 Worker 仍按任务自动分配，不新增手动 Worker 组。Worker 模型可跟随实例默认模型或独立指定服务、模型、思考级别；Router 独立模型放在组织与大脑的高级设置中。
- 保留已有 `model` 语义，新增可选 `roleModels.worker`、`roleModels.router`、`workerSkills`。没有新字段的配置仍可读取。保存及启动时校验模型、工具和技能可用性；旧工具勾选不自动扩展。日常对话继续使用原模型配置与原入口。
- 从真实执行预设读取工具、从对应实例工作目录读取 DSH 技能注册表。探测发生在未发布的 Session setup 事务中，并回滚，不触发模型调用。不可用工具灰显；已保存但失效的选项保留可见，保存时拒绝无效配置。
- 当前安装宿主实际提供 `read/glob/grep/read_image/write/edit/pwsh`。已实现的 `bash/web_search/web_fetch` 适配仅在宿主提供原生定义时可选择；本机未提供这些工具。没有新增远程连接或自动安装工具插件。
- 所选技能在每次 Worker 执行前加载真实正文及资源目录，按请求保存快照，只作用于 Worker。技能不增加工具权限；缺失或不可供模型调用的技能会使执行失败，不伪装加载成功。

## 实现边界与影响

原进程配置、委派契约及 core 的授权证明校验均只接受三个只读工具，单改页面或 Jarvis 适配器无法让新工具经过原有验证链。因此只扩展原 core 的工具名称类型与验证集合，并保留宿主可信证明、固定父子关系、双方工具交集、迟到结果隔离及单跳限制。其余授权和任务状态规则未重构。

原生文件读写路径经过实际路径解析；写入只接受实例工作目录，所选技能资源目录仅增加读取范围。命令的工作目录限定为实例目录，但命令本身依赖宿主账号及 DSH 策略，不能当作完整操作系统隔离；页面明确说明这一点。命令仅允许前台、最长 30 秒；原生工具若晋升为后台任务，会取消并等待清理，不交出可继续运行的后台任务入口。未增加长任务委派能力。

模型覆盖会在恢复旧 Session 后继续生效，撤销覆盖会恢复实例默认值。根日常对话的逐轮模型快照仍优先；没有切换旧聊天、迁移历史或接管旧任务。此前已实现的会话基础代码随发布快照一起存在，但用户入口仍保持原路径。

真实宿主联调发现并修正两项兼容性：使用当前 Jarvis 可用预设，避免已安装 DSH 默认预设引用未注册的 subagent；将 DSH 自动插入的 `time-context` 与既有 `runtime-context` 一样识别为宿主上下文，真正的额外用户请求仍被轮次身份校验拒绝。
