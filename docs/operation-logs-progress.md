# 运行日志模块实施记录

## 用户目标与边界

用户要求查看完整、详细的运转日志，以理解对话、交办、路由、Worker、工具、下级委派、结果反馈与异常。日志是独立的运行查看入口，不混入角色模型配置，不新增业务开关，不修改任务授权或调度。

## 数据原则

- 基于已知且归属本产品的会话和受管目录读取证据，不能扫入其他 DSH 会话。
- 区分原始会话事件、已持久化业务记录和采集时的状态快照。不存在的历史步骤不补造；缺失、回补和不可用来源明确显示。
- 保留原事件身份、时间与任务关联；独立 SQLite 仅存日志索引和脱敏明细，不接管业务数据库。
- 读取日志不调用会推进任务的 state/query/pump 接口，不启动或重试任务。
- 凭据、认证字段及令牌在进入日志库和响应前脱敏；日志读取沿用登录与同源边界。
- 列表按收录顺序分页，明细按需读取；保留原事件时间，不把回补顺序说成发生顺序。

## 界面

入口统一在“设置”页右上角，按用户 2026-11-16 的明确要求移除聊天顶部的重复入口；仍独立整页查看。支持关键词、组织、角色、级别筛选，查看同一流程、展开事件明细、加载更多、暂停刷新与导出当前记录。沿用设置路由的草稿保护；日志页显隐不销毁正在回复的对话。

## 实际覆盖与限制

- 日常贾维斯、任务路由、普通 Worker 及独立组织通过已登记的会话标识收录模型请求、输入、回复、工具参数、工具返回和结束原因；不遍历无关会话。
- Core/Gateway 与独立组织的既有数据库以只读查询方式收录任务、路由决策、交办、派工、委派、反馈及通知状态。可变记录是状态快照，采集间隔内未留存的中间变化无法恢复；实例生命周期来自持久事件文件。
- 历史会话按序号分页回补，实时事件按来源身份去重。单次对话可关联多个独立任务；跨组织流程使用已保存的任务／委派关系，不按名称或最近时间猜测归属。
- 底层进程标准输出尚未纳入。超过单条 4 MiB 的详情只保存明确的省略说明、大小与摘要校验值；页面不会将省略记录显示为完整。
- 导出范围是当前选中事件。页面支持筛选和继续加载历史，不宣称提供全量归档导出。
- 原日常对话仍走既有入口，本模块没有迁移对话或任务执行路径；独立日志库初始化失败时原聊天和设置继续工作。
