# 独立实例会话接入进度

2026-11-15 用户暂时无法测试，授权继续推进。核对现有入口后，先补齐独立进程的会话传输基础，再接日常聊天；不因接入而丢失已有会话能力。

## 本轮范围

- 根实例会话读取、逐步输出、按用户轮次精确停止，以及后台事件的完整分页。
- 历史默认读取最近 20 条，按稳定游标向前翻页；每页 JSON 至多 1 MiB，减少条数而不截断正文。当前回复单独读取，流式轮询不反复搬运全部历史。
- 请求固定宿主管理器的随机 `runtimeId` 和实例运行代次 `generation`；管理器重建、宿主重启或实例重启后，旧绑定不得继续读取或取消新进程。重复请求查询原结果，不自动重放。
- 保持原用户聊天、历史、模型设置及任务关联。新接口只允许根实例，复用宿主登录、同源和 CSRF 校验。
- 不实施历史迁移、会话切换、清空、重新生成、通知自动表达或自动启用实例；这些行为需要沿用旧入口的会话归属与防重复规则，不能用简单代理冒充完整接入。

## 分工与验证

- ProcessRuntime 持有用户轮次和反馈游标，验证更新身份；DSH bridge 转送当前用户请求的文本流，凭据和实际模型执行仍留在宿主。
- ProcessManager 在调用前后核对运行代次，HTTP 层复用现有 NDJSON 事件结构，断连只取消该请求。
- 针对停止隔离、迟到输出、崩溃恢复、分页超过 50 条、认证、重复请求与断连建立自动验证；随后使用隔离宿主验证实际 DSH 事件。
- 进度及日志写入 `.artifacts/root-chat/`。长任务无专用 Codex 委派工具，检查按有界批次执行；联调宿主独立隐藏进程运行并记录 PID、输出和状态。

## 模块和接口

| 模块 | 本轮职责 |
| --- | --- |
| `src/process-runtime/runtime.ts` | 用户轮次、部分回复和恢复状态落盘；精确取消；Gateway 反馈分页与当前问题身份 |
| `jarvis/process-runtime/reply-progress.mjs` | 订阅 DSH 当前用户轮次的可见文本事件，合并累计快照；不输出推理内容，不累积无界消息队列 |
| `jarvis/process-runtime/dsh-bridge.mjs` | 当前请求的流式订阅及取消身份核对；正式结果仍读取 DSH Session |
| `jarvis/process-runtime/manager.mjs` / `child.mjs` | 有身份约束的 IPC 调用和进程代次检查 |
| `jarvis/process-runtime/conversation-http.mjs` | 固定根实例的安全公开投影、流式传输、断连处理与宿主运行标识 |
| `jarvis/dsh/index.mjs` | 在现有认证、同源和 CSRF 检查后分派新接口 |

HTTP 路径均以 `/jarvis/api/system/root/conversation` 为前缀：

| 方法与路径 | 请求与结果 |
| --- | --- |
| `GET /` | `before?`、`limit?`；最近历史、`nextCursor`、当前用户轮次及运行绑定 |
| `POST /chat` | `runtimeId`、`generation`、`id`、`text`、可选任务／问题引用；NDJSON `start/replace/done` |
| `POST /stop` | `runtimeId`、`generation`、`id`；只停止该用户回复，返回是否确认停止 |
| `GET /events` | `cursor?`、`limit?`；原始业务反馈及当前问题身份，不冒充已由贾维斯表达的通知 |

表中的 `GET /` 指前缀本身，无结尾斜杠。`runtimeId` 是运行绑定标识，不是登录凭据；DSH 登录与 CSRF 仍必需。GET 用于重新取得当前运行绑定，未来前端仍须核对响应归属，不能把新绑定的返回直接混入旧视图。运行绑定在 RPC 前后、轮询和断连取消时均检查，不能只在入口检查一次。新发送最多 20000 字符，未知字段及未实现的 retry/clear 明确拒绝。

流只有核对到已保存的相同消息 ID、原文和任务选择后才发 `start`。重复 HTTP 流关闭不能取消原请求；原拥有者断连后只核对、取消自己已接受的轮次。结果不明时结束流并保留记录，不伪造成功、不重发模型调用。

用户回复即使被 DSH 标为完成，只要没有可见文字，也须记为未完成并提示核对已提交任务。已显示片段保留；同一消息重发只返回原记录。Router、Worker、机器委派的无文字完成不受此用户表达规则影响。

## 后续实施：对话模型设置衔接（2026-11-15）

用户再次要求“继续”后，核查到不能直接切换原聊天：旧 UI 历史、完整 DSH Session 和旧任务 ledger 各有归属，复制展示文字不能恢复模型上下文；把旧前台摘要再传给新 root.chat 会多跑一次大脑，还会把摘要冒充新的真实用户消息。因此先落实模型配置衔接，保留唯一入口及原数据，后续再实施显式会话接管与旧任务归属路由。

本次新增 `jarvis/dsh/conversation-model.mjs`，直接读取现有 Store 的 `dsh-model`，复用已有参数解析和 callConfig。现有模型设置仍是日常对话参数的唯一来源；不建立第二份可编辑配置。每条 root 用户请求在第一个异步边界前固定版本、模型、思考级别、温度、输出上限、回复超时和流式显示偏好，保存无凭据快照。同一轮工具往返使用同一快照，下一轮才采用新设置。无效配置拒绝处理，不静默换用实例模型。

限定范围为 `instanceId=root / role=jarvis / sessionKey=jarvis`。Router、Worker、下级实例和机器委派准备会话保留原实例模型；修改对话设置不重启后台任务。助手名称与实例大脑名称、原生工具策略仍待后续明确接管，本轮没有覆盖或重新解释它们。

实际 DSH `agent/request` 是逐步调用的 waterfall，中间件须 `await next()` 后返回完整快照；不是给 `next` 传参数，也不是只修改 Agent 创建参数。返回完整配置确保用户清空可选参数后不继承旧的推理强度或输出上限。已完成、待恢复的重复请求均沿原记录核对，不因为模型配置改变而重新执行。

回复超时按现有 1–3600 秒范围执行。root 用户调用的两段 IPC 使用 3630 秒有限预算，为宿主取消、保存留余量，避免默认 120 秒提前截断；其他 IPC 仍用原预算。关闭流式显示时仍保存部分回复，仅在 HTTP 的运行中投影隐藏；完成、失败或恢复后保留可见文字。同轮显示策略固定，迟到更新不能翻转。

本轮不迁移历史、不启用 UI 切换、不更改 Core 任务规则，不新增 Worker 组或远程服务。4318 保持原发布，以上能力尚未部署。实施与审查证据在 `.artifacts/root-binding/`；后续切换仍需完成原文列出的历史/任务绑定、通知抢占、清空与重试等门槛。
